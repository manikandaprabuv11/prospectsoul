Why now — two realities from the source file

Seven of the twelve ICP fields are empty on registry import. A single company routinely carries multiple NIC codes. Maximum observed in one file: 91.

Analysis of the full Kanchipuram MSME registry found that 21% of rows carry more than one NIC code, and that phone, website, GST, turnover, and headcount are entirely absent. Design accommodates this — multi-NIC via join, nullable everything, dedup rule ⓪ on source_reference so re-imports don't swamp the Triage Queue with 15,002 duplicated proprietor names.

5Companies List Download is distinct from pipeline Export

CREATE TABLE company_nic_codes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  nic_code_id UUID REFERENCES nic_codes(id),      -- NULL when raw unmatched
  nic_code_raw VARCHAR(6) NOT NULL,
  description_raw TEXT,
  is_primary BOOLEAN NOT NULL DEFAULT false,
  sequence_no SMALLINT NOT NULL,
  UNIQUE (company_id, nic_code_raw)
);

-- Enforce Invariant 12 at DB level
CREATE UNIQUE INDEX idx_cnc_one_primary_per_company
  ON company_nic_codes(company_id) WHERE is_primary = true;

Recursive descendant expansion

WITH RECURSIVE subtree AS (
  SELECT id FROM nic_codes WHERE id = :parent
  UNION ALL
  SELECT n.id FROM nic_codes n JOIN subtree s ON n.parent_id = s.id
)
SELECT DISTINCT c.* FROM companies c
JOIN company_nic_codes cnc ON cnc.company_id = c.id
WHERE cnc.nic_code_id IN (SELECT id FROM subtree);

22 · Claude Kickoff Prompt

Twelve constraints. None negotiable.

Before Claude Code writes a line of code, it reads all authoritative docs, inspects the repo, and produces a gap assessment.

The twelve constraints

  1. Do not recreate companies or contacts. Additive ALTER TABLE only.
  2. NIC is optional everywhere. Absent → no rows, no error.
  3. A company can carry multiple NIC codes and multiple contacts. Scalar-column shortcuts forbidden. One row has 91 NIC codes.
  4. Contact role required on new contacts, from contact_roles. is_md_owner preserved and kept in sync.
  5. Resolve NIC parents by longest existing prefix, not fixed-length truncation.
  6. NIC master import must NOT create import_batches rows.
  7. Pincode external search must not fetch from companies. External results never persisted automatically.
  8. "+ Add" routes through the existing manual-entry endpoint. No second creation path.
  9. Places API key server-side only. Maps JS key separate, origin-restricted.
  10. Do not rename or repurpose "ICP". NIC filtering ≠ ICP Qualification.
  11. "Download" ≠ "Export". Two endpoints, two verbs, one meaning each.
  12. Everything nullable stays nullable. The 7-column sample must succeed.

ADR-on-demand policy

Do not create /adr at project setup

The folder is created only when Claude Code actually changes existing code, existing flow, or deviates from docs 01–22 during implementation. At that moment:

  1. Create /adr at repository root if it does not exist
  2. Create /adr/README.md with the template (in doc 22)
  3. Add one ADR file per behavior-changing decision: ADR-NNNN-<slug>.md
  4. Number sequentially starting at 0001

Not required for: new code that follows the specs as written, cosmetic refactors within a single new module, bug fixes in your own new code.

Definition of done

Do not claim completion until every criterion in doc 21's Release Gate passes, with evidence per criterion. Claude Code reports PASS/FAIL/BLOCKED per criterion per track, not summary claims.
